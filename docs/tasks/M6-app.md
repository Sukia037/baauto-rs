# M6 · app：三欄介面、手牌校準、錄點與最終驗收

> 規格依據：v0.4 §3、§9、§9A、§10、§12、§13
> 前置：M3、M4、M5　｜　環境：本機 Windows　｜　建議 effort：中　｜　完成後複查：抽查

## 目標

把 M3 的 headless 控制程序變成完整的桌面程式。**介面用使用者選定的三欄版**：上方兩列分別是點位 JSON（含六人／十人）和預設按鍵 JSON 的檔案按鈕＋完整路徑，目前用哪兩個檔一定看得到、各自一鍵切換；每個分頁都是「清單＋右邊詳細」。像 AHK 版一樣保留候選點位和點位按鍵清單，牌鍵就是點位按鍵清單裡功能為「牌鍵」的項目（取代原本的拖曳）；手牌設定是這台電腦的設定。不放說明段落、群組框、示意圖或裝飾。GUI 只負責編輯、顯示和下指令，永遠不直接送遊戲輸入。最後完成功能對照與 8 小時長時間測試。

## 範圍

### 要做
- `bins/baauto-app` 的 GUI（`eframe`／`egui`），照下面的版面與視覺規則。
- 點位 JSON 與預設按鍵 JSON 各自的切換、開啟其他位置的檔、另存、重新載入、新增；點位檔的六人／十人切換。
- 手牌校準覆蓋層：在遊戲畫面上畫出手牌框和格線，拖拉調整；也可以在點位分頁選一個牌鍵，在右邊直接輸入數字。
- 普通點位錄製：覆蓋層＋引擎 Hook 攔下那一下點擊。
- 熱鍵擷取：由引擎 Hook 轉交下一個輸入（抓得到側鍵、滑鼠鍵、Space、Tab）。
- 遊戲畫面檢查：遊戲不是全螢幕 16:9 時在狀態列警告。
- 舊檔匯入精靈、報告入口。
- 依 M5 的實驗結果決定引擎優先權與尾段自旋。
- 功能對照驗收與長時間測試。

### 不做
- 下面沒列到的新功能。

## 版面

> 可以點的參考：`docs/pages/BAauto-新介面Demo.html`（瀏覽器開，三欄版，使用者已選定）。資料都是示範值。Demo 和這份任務檔或規格不一致時，以規格與任務檔為準。

原則：**目前用的是哪個點位 JSON、哪個預設按鍵 JSON，一定看得到、各自一鍵就能切換**；每個分頁都是「清單＋右邊詳細」，資訊要有，但不放說明段落、群組框、示意圖。

```text
│ 點位     [一般關卡.json*|總力戰 ホド.json|…] [新增][開啟…] [六人|十人] C:\BAauto\points\一般關卡.json  另存… 重新載入 │
│ 預設按鍵 [預設按鍵.json|校準後.json]         [新增][開啟…]            C:\BAauto\keys\預設按鍵.json    另存… 重新載入 │
│ (點位) 預設按鍵  時間  紀錄                                  存在點位 JSON：一般關卡.json │
├──────────────────────────────────────────────────────────────────────────────┤
│ 候選點位        │ 點位按鍵清單（名稱／熱鍵／功能／位置／狀態） │ 詳細（選到的那一筆）       │
├──────────────────────────────────────────────────────────────────────────────┤
│ 一般關卡.json、預設按鍵.json 有未儲存的變更                         [還原] [儲存] │ ← 只在有變更時出現
│ ● 引擎正常   遊戲在前景   游標：第 2 格                           Ctrl+F9 緊急停止 │
└──────────────────────────────────────────────────────────────────────────────┘
```

**兩種 JSON（和 AHK 版一樣分開）＋這台電腦的設定**

| 放在哪 | 內容 |
|---|---|
| 點位 JSON（`points/`，每個關卡或 Boss 一份） | 六人／十人、點位按鍵清單（普通點位＋牌鍵） |
| 預設按鍵 JSON（`keys/`，像原本的 function_keys.json） | 23 個預設按鍵的熱鍵與啟用、時間 |
| 這台電腦的設定（`settings.json`，不出現在檔案列） | 手牌位置左右、格的順序、四組手牌範圍（六人／十人 × 左右）、每格按鍵 |

- 兩列各自是開著的 JSON 分頁（顯示檔名），目前的那個反白，有未儲存的變更時檔名後面加 `*`。檔案多時這排可以左右捲，目前的檔一定捲到看得到。旁邊是「新增」「開啟…」。第一次啟動時開著資料夾裡所有的檔，之後記住開著哪些分頁。
- 每個分頁有「×」：先問「關閉分頁」（只從這一列拿掉，檔案還在，可以再用「開啟…」打開）或「刪除檔案」（移到該資料夾的 `.trash/`），有未儲存的變更要寫出來。每一列至少留一個分頁，不能關掉最後一個。關掉的是目前用的檔時，先走停止協定，再改用旁邊那一個。
- 點位那一列另外有「六人｜十人」切換，改的是這個點位檔的模式（會變成未儲存）。
- 「開啟…」用 Windows 的開啟檔案對話框開**任何位置**的 JSON（別的磁碟、網路磁碟、OneDrive、中日文、長路徑都要能開），也可以把檔案拖進視窗。看內容判斷是點位還是預設按鍵：從哪一列開都可以，會放到對的那一列並在狀態列說明。開過的加進分頁列（完整路徑記在 `settings.json`）。舊版 AHK 檔走 M4 匯入：轉出的新檔預設存在原檔旁邊、檔名加「（新版）」，原檔不動。
- 「新增」「另存新檔」都可以選任何資料夾，預設是目前那個檔所在的資料夾；檔名不能有 Windows 不允許的字元。
- 同名不同資料夾的檔，分頁上加資料夾名稱區分；滑過分頁顯示完整路徑。記住的檔不見了，分頁標「找不到檔案」，可以重新指定或關閉。
- 每列都顯示完整路徑、「另存新檔」「重新載入」。
- 切換、開啟、新增時，如果**那一種**檔有未儲存的變更，先問：「儲存後切換」「不儲存」「取消」（有錯不能存時只給後兩個）。換點位檔不影響預設按鍵檔，反之亦然。
- 切換一律走停止協定：停止 → 載入 → 原本在運作的話，等按鍵放開後繼續（和 M3 的失焦重新啟用同一套規則）。
- 分頁列右邊寫目前分頁的資料存在哪個檔（點位 → 點位檔，預設按鍵、時間 → 預設按鍵檔）。
- 手牌設定是這台電腦的設定，改了馬上存進 `settings.json`，不出現在「未儲存的變更」裡。

**分頁**

| 分頁 | 左／中 | 右邊詳細 |
|---|---|---|
| 點位 | 左：候選點位（錄製或 MuMu 匯入的點，名稱＋座標，上方「＋ 錄製」）。中：**點位按鍵清單**——像 AHK 版一樣一張清單，每一筆有名稱、熱鍵、功能（普通點位／牌鍵）、位置（普通點位是遊戲畫面座標，牌鍵寫「手牌」）、狀態，有問題的排最上面；上方「＋ 牌鍵」 | 選到普通點位：名稱、熱鍵、功能、X、Y（遊戲畫面像素）、狀態原因；重錄位置、移回候選、刪除。**沒有座標基準的選項**：新錄的一律是遊戲畫面座標，舊檔在匯入時轉好，轉不了的狀態寫「舊座標，請重錄」。選到牌鍵：名稱、熱鍵、功能、狀態，下面是手牌（這台電腦的設定，所有點位檔共用）：位置右／左、格的順序、左上／右下、每格按鍵（六人 3 格、十人 5 格）、校準狀態與「在遊戲上校準」、按住時是否重複；鏡像到另一邊、還原預設、刪除。選到候選：座標、來源、「帶入點位按鍵清單 →」（變成普通點位後直接進熱鍵擷取） |
| 預設按鍵 | 23 個功能依「技能、技能連點、卡幀開牌、其他」分組；每列：名稱、按鍵標籤、狀態（啟用／停用／和誰重複；目前點位檔是六人時，4、5 號註明「六人沒有第 N 格」但照常啟用）；右上「恢復全部預設」 | 功能說明、熱鍵、啟用開關（緊急停止一定啟用）、修飾鍵必須完全一致、狀態、預設值與「恢復這一項」 |
| 時間 | **照規格 §5 的表顯示**（2026-10-12 使用者決定）：每個功能一列，欄位是功能、熱鍵、按下時、放開時；「按下時」「放開時」把動作順序寫成 `Esc →〔16〕→ Esc` 這種一行，`〔 〕` 就是可以直接改的數字（ms）。同一列共用一組；沒有間隔的列（普通暫停、AUTO／加速／技能、緊急停止、錄製）照樣列出、沒有輸入格。熱鍵欄只顯示，改熱鍵在「預設按鍵」分頁。數字不合法時那一格標紅 | 這組時間的驗證狀態與來源、載入校準結果、還原範本值；選到的一列：每個間隔的 JSON 欄位名、用途、規則、錯誤、「恢復這一列預設」 |
| 紀錄 | 事件清單（時間＋一句話，問題用紅點／黃點） | 報告與 `logs/fault-*.csv` 清單，「開啟」用預設程式開；「開啟資料夾」 |

**改熱鍵**：點任何按鍵標籤 → 變成「按下按鍵…」，狀態列顯示提示 → 按下鍵盤鍵或滑鼠右鍵、中鍵、側鍵就設定；Esc 取消；Backspace 清除（每格按鍵不能清除，也不收滑鼠鍵）。左鍵不能當熱鍵，點別的地方就取消。

**衝突規則（照 AHK 版）**：預設按鍵彼此重複，兩邊都停用、預設按鍵檔不能存；點位按鍵清單裡的項目撞到預設按鍵或彼此重複，該項停用並寫出和誰重複，點位檔照樣可以存。

**存檔**：編輯只改記憶體，底部出現「<檔名>、<檔名> 有未儲存的變更」和「還原」「儲存」（兩種檔有變更的都存）。儲存走：停止 → 原子存檔 → 套用 → 原本在運作的話，等按鍵放開後繼續。預設按鍵檔有錯（預設按鍵重複、時間不合法）時，底部改成紅字寫原因，「儲存」停用。

**狀態列**：平常顯示引擎狀態、遊戲是否在前景、游標在第幾格（遊戲在前景時 10–20 次／秒更新，只是顯示，不影響引擎判定）。錄點、改熱鍵或剛做完某個動作時，暫時換成一句提示。

## 視覺規則

- **少就是好**：不放說明段落、群組框、示意圖、縮圖、插畫或大圖示。座標、毫秒、熱鍵直接顯示數字和文字。唯一的圖形是手牌校準時畫在遊戲上的覆蓋層。
- **三欄一致**：每個分頁都是清單在左（或左＋中）、詳細在右；選到哪一筆，右邊就顯示它的全部設定。清單列高一致（約 34px），用細線分隔。
- **按鍵標籤**：熱鍵一律顯示成小鍵帽（等寬字型）；沒設定是虛線框，重複是紅框紅底，停用是淡色。
- **字型**：egui 內建字型沒有中文。啟動時先載入系統的「Microsoft JhengHei UI」，找不到再用內嵌的 Noto Sans TC 子集；檔名、路徑、熱鍵用等寬字型；數字用等寬數字。
- **顏色**：跟著系統淺色／深色。一個強調色，只用在主要按鈕、選取、開關。目前分頁用實心膠囊。狀態色只有三種：綠＝正常、黃褐＝注意、紅＝問題，一定同時寫出文字。
- **文字**：按鈕寫動作（「綁成點位按鍵」「儲存」），錯誤寫原因和怎麼修，一句話就好。
- **視窗**：預設 960×620，最小 900×560；記住上次大小、分頁、目前的點位檔與預設按鍵檔、開過的 JSON；1.5 倍、2 倍 DPI 不跑版。

## 手牌校準覆蓋層

1. 在點位按鍵清單選一個牌鍵，右邊按「在遊戲上校準」，遊戲需要在戰鬥畫面且在前景。開始校準時引擎先走停止協定、維持 Disarmed，校準結束才恢復。
2. 覆蓋層（`egui` viewport：置頂、透明、無邊框；拖拉時接收滑鼠，其餘穿透）在遊戲上畫出目前模式（看點位檔）與位置的手牌框，切成 3 或 5 格，每格標上編號和對應的按鍵。
3. 兩種調整方式：拖拉框的邊和角；或者「依序點第 1 格中心、最後一格中心」，自動算出整個框。
4. 可以切換右／左預覽；「鏡像到另一邊」把目前的框左右鏡像給另一邊當起點。
5. 確認後寫進 `settings.json` 的那一組手牌矩形（`calibrated: true`），所有點位檔共用。
6. Esc 取消；校準模式一定有逾時。

## 普通點位錄製

1. 使用者按「錄製點位」或 Ctrl+F10（監督執行緒的全域熱鍵）。
2. 控制程序送 `BeginRecordPoint` → 引擎 Hook 進入錄點模式：下一次左鍵點擊**攔下不送進遊戲**，回報螢幕座標。
3. 覆蓋層跟著游標顯示目前的遊戲畫面座標。
4. 引擎回 `PointRecorded { screen_pos }` → 控制程序換算成遊戲畫面 0–1 座標 → 加入候選點。
5. Esc 取消錄點。錄點模式一定有逾時，逾時自動結束。

IPC 新增：`BeginRecordPoint`、`CancelRecordPoint`、`PointRecorded`、`CaptureNextInput`、`CapturedInput`。這些都只在 Disarmed 時允許，不能和正常運作同時進行。手牌校準只用 GUI 自己的覆蓋層，不需要引擎參與。

## 熱鍵擷取

- 點熱鍵欄位 → 控制程序送 `CaptureNextInput` → 引擎 Hook 把下一個實體輸入（含修飾鍵組合）回報為 `Chord`，並攔下不送出。
- 預設產生 `AtLeast`，介面提供「修飾鍵必須完全一致」的選項（對應 JSON 裡的 `=` 前綴）。
- 擷取到左鍵：拒絕並提示。

## 遊戲畫面

- 遊戲一律當成全螢幕 16:9，遊戲畫面＝遊戲所在的整個螢幕。不做視窗化、黑邊或內容區校準的介面。
- 遊戲不是全螢幕 16:9（引擎回報 `NotFullscreen16x9`）：狀態列警告「遊戲不是全螢幕 16:9，點位和牌鍵會不準」。平常狀態列顯示目前解析度，例如「全螢幕 2560×1440（16:9）」。
- 座標存 0–1，介面顯示成目前解析度的像素；換 16:9 的其他解析度不用重錄。

## 其他規定

- 主視窗按 Esc 不結束程式。關閉視窗時先走停止協定，再結束兩個程序。
- 在建立任何視窗之前設定 Per-Monitor DPI Awareness V2（如果 `winit` 已經設定，確認一次並寫在註解）。
- GUI 執行緒不等監督執行緒，也不讓監督執行緒等它。
- 所有編輯走 M4 的 `config::editor`，所有存檔走 `config::store`，GUI 本身不直接改資料結構。

## 優先權與自旋的定案

- 讀 M5 的實驗結果，照規格 §3 的規則決定引擎優先權和尾段自旋要不要開、開多長。
- 決定和數據寫進 `docs/decisions.md`；設定值放在 `EngineParams`，不寫死在程式裡。
